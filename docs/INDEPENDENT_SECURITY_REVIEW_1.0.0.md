# 1.0.0 独立安全复核包

此文档定义外部复核者需要检查的固定范围。项目维护者的自动扫描和自审不能填写 `independentReview: passed`。

## 待复核对象

- 最终 OpenSource EXE 及其 SHA-256。
- 与该二进制对应的 Git commit、构建依赖锁、第三方许可证和可复现构建报告。
- 原生宿主、HTTP API、WebView2 边界、任务与工作区路径、CLI 子进程、权限代理、更新器、插件/Skill/MCP 安装、凭据存储和日志脱敏。

## 必做检查

1. 验证源码和二进制摘要，复现构建并解释任何字节差异。
2. 审查本机 HTTP 服务的回环绑定、随机端口、DPAPI 保护、请求密钥、协议版本、Origin 与跨站请求边界。
3. 审查路径规范化、符号链接/重解析点、压缩包解包、插件下载、命令参数转义和工作区逃逸。
4. 审查权限模式到各 CLI 内核的映射，确认拒绝、超时、重启和队列转向不会扩大权限。
5. 审查 API 密钥不可明文回显、日志/诊断导出脱敏、归档和删除行为，以及更新回滚的完整性检查。
6. 运行依赖漏洞检查、秘密扫描、C# 与 JavaScript 静态分析、恶意输入测试，并记录未能运行的工具或规则。
7. 对每项高危或严重发现给出复现步骤、影响、修复 commit 与同一候选复测结果。

## 签署要求

- 复核者必须独立于本次实现者，并写明姓名或组织、联系方式或可验证身份、复核日期和工具版本。
- 所有高危与严重问题关闭后，复核者才可生成 `release-evidence/1.0.0/security-review.json`，其中 `independentReview` 为 `passed` 且 `unresolvedHighOrCritical` 为 `0`。
- 任何范围限制、未运行检查或未解决问题都必须写入 findings；不得用自动扫描零告警替代独立结论。

## 当前维护者证据

- 72 项离线回归结果及每项 stdout/stderr/退出码。
- Pi 与 DSH 生产依赖 `npm audit --omit=dev --audit-level=high` 零漏洞结果。
- `tests/release-security-audit.ps1` 的发行文件、个人路径、凭据形状和签名检查结果。
- Windows 矩阵、读屏人工清单、72 小时四内核负载和可复现构建证据，均必须绑定最终 EXE SHA-256。
