# 1.0.0 无障碍认证清单

本清单用于对最终候选 EXE 做人工键盘与读屏验收。自动化无障碍树、ARIA 状态和焦点测试只能作为前置证据，不能替代实际朗读。

## 固定候选

- 记录 EXE 文件名、SHA-256、Windows 版本、WebView2 版本、缩放比例和显示语言。
- 分别使用 Windows Narrator 与当前稳定版 NVDA；记录读屏器完整版本。
- 从全新工作区开始，并使用至少一个含过程、命令、代码块、表格、附件和最终回答的真实任务。

## 键盘验收

1. 仅用 Tab、Shift+Tab、Enter、Space、方向键和 Escape 完成新建任务、发送消息、切换任务、打开设置并返回。
2. 打开与收起整个过程；逐项打开与收起思考段、命令、运行证据和文件预览。焦点必须留在触发按钮或进入新面板的第一个可操作项。
3. 打开定时任务和插件页，再点“新建任务”。页面必须切回编辑器，未发送的草稿不得因误触丢失，空任务不得出现在侧栏。
4. 打开所有对话框与抽屉。Tab 不得逃出模态区域，Escape 关闭后焦点回到原按钮。
5. 在 200% 缩放和高对比度主题下重复主要路径；不得出现不可见焦点或只能用鼠标完成的操作。

## 读屏验收

1. 启动后读出产品名、当前任务、主导航和任务输入框；同名按钮应有可区分名称。
2. 新消息只朗读一次。流式输出不得反复重读整个对话；完成后能定位“Agent 最终回复”。
3. “整个过程”、思考段和命令项应读出按钮名称及展开/收起状态。状态变化后读屏器必须报告新状态。
4. 表格应报告行列关系；代码块应作为独立内容读取；行内代码不得被误报为空按钮。
5. 定时任务、插件详情、设置、文件预览和权限提示应读出标题、控件名称、当前值、错误和成功状态。
6. 后台任务完成、失败和权限等待应通过状态区域报告，同时不能抢走正在输入的焦点。

## 通过条件

- 上述步骤在 Narrator 和 NVDA 中均无阻断性问题。
- 所有严重和高等级问题均已修复并以同一 SHA-256 候选复测。
- 审核者填写姓名或组织、日期、工具版本、发现清单和结论；据此生成 `release-evidence/1.0.0/accessibility.json`。
- 无实际朗读记录时，`screenReader` 必须保持 `not-run`，不得标记为 `passed`。
